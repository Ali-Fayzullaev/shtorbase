# Модуль «Уведомления»

← [Назад к обзору](./00-overview.md)

## 1. Что уже работает

`notifications` (таблица), in-app колокольчик (`NotificationBell`), интеграция с Telegram (`lib/telegram.ts`, `broadcastTelegram`) — всё уже реализовано и рассылает уведомления о новых заказах и смене статуса.

## 2. Проблема

Сейчас в `updateOrderStatus` уведомление о смене статуса уходит **исполнителю** (`assigned_to`), если статус меняет кто-то другой. Но по бизнес-процессу нужно обратное направление: когда **сотрудник** отмечает заказ готовым, уведомление должно прийти **менеджеру** (создателю заказа), а не наоборот.

## 3. Целевая логика

| Событие | Кому | Канал |
|---|---|---|
| Новый заказ создан менеджером | Всем сотрудникам (если в общую очередь) или назначенному | in-app + Telegram — уже есть |
| Сотрудник принял заказ (`acceptOrder`) | Менеджеру/создателю заказа | in-app + Telegram — **новое** |
| Заказ отмечен готовым (`completeOrder`) | Менеджеру/создателю заказа | in-app + Telegram — **новое, приоритет P1** |
| Менеджер вручную сменил статус | Исполнителю (`assigned_to`) | in-app + Telegram — уже есть, не трогаем |

## 4. Реализация

В новых Server Actions `acceptOrder`/`completeOrder` (см. [02-production.md](./02-production.md)) после смены статуса:

```ts
if (order.created_by && order.created_by !== user.id) {
  await createNotification(
    order.created_by,
    action === 'accepted' ? 'Заказ принят в работу' : 'Заказ готов',
    `Заказ #${orderId.slice(0, 8)} — ${action === 'accepted' ? 'принят сотрудником' : 'готов к выдаче'} (${assignedProfile.full_name})`,
    `/orders/${orderId}`
  )
}
```

Плюс аналогичный `broadcastTelegram` с новым шаблоном (`tgOrderAccepted`, `tgOrderReady` в `lib/telegram.ts`, по аналогии с уже существующими `tgNewOrder`/`tgStatusChanged`).

## 5. Звуковое/визуальное уведомление (опционально)

По исходному ТЗ — «опционально звуковое или визуальное уведомление» для менеджера о готовности заказа. Предложение: короткий toast (`sonner`, уже используется в проекте) + системный `Notification` API браузера, если пользователь разрешил (не блокирует MVP, приоритет P2).
