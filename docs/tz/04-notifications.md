# Модуль «Уведомления»

← [Назад к обзору](./00-overview.md)

> **Статус: ✅ реализовано** в рамках шага 2 ([02-production.md](./02-production.md)) — `acceptOrder`/`completeOrder` в `lib/actions/orders.ts` уведомляют создателя заказа. Раздел ниже оставлен как описание реализованной логики.

## 1. Что уже работает

`notifications` (таблица), in-app колокольчик (`NotificationBell`), интеграция с Telegram (`lib/telegram.ts`, `broadcastTelegram`) — всё уже реализовано и рассылает уведомления о новых заказах и смене статуса.

## 2. Была проблема (исправлено)

В `updateOrderStatus` уведомление о смене статуса уходит **исполнителю** (`assigned_to`), если статус меняет кто-то другой — это верно, когда статус меняет менеджер. Но когда **сотрудник** сам принимает/завершает заказ через новые `acceptOrder`/`completeOrder`, уведомление должно приходить в обратную сторону — **менеджеру/создателю заказа**.

## 3. Реализованная логика

| Событие | Кому | Канал |
|---|---|---|
| Новый заказ создан менеджером | Всем сотрудникам (если в общую очередь) или назначенному | in-app + Telegram |
| Сотрудник принял заказ (`acceptOrder`) | Менеджеру/создателю заказа | in-app + Telegram ✅ |
| Заказ отмечен готовым (`completeOrder`) | Менеджеру/создателю заказа | in-app + Telegram ✅ |
| Менеджер вручную сменил статус | Исполнителю (`assigned_to`) | in-app + Telegram — не трогали |

## 4. Реализация

Хелпер `notifyCreator()` в `lib/actions/orders.ts` (вызывается из `acceptOrder` и `completeOrder`) — уведомляет создателя заказа через `createNotification` и переиспользует существующий шаблон `tgStatusChanged` из `lib/telegram.ts` (он уже достаточно общий: принимает `oldStatus`/`newStatus`/`changedBy`, отдельные Telegram-шаблоны заводить не понадобилось).

## 5. Звуковое/визуальное уведомление (опционально)

По исходному ТЗ — «опционально звуковое или визуальное уведомление» для менеджера о готовности заказа. Предложение: короткий toast (`sonner`, уже используется в проекте) + системный `Notification` API браузера, если пользователь разрешил (не блокирует MVP, приоритет P2).
