# UI/UX требования — планшет для производства

← [Назад к обзору](./00-overview.md)

## 1. Кто использует планшет
3 сотрудника производства — основной сценарий: стоя у стола, руки часто заняты тканью/инструментом, экран смотрят кратко, тапают одной рукой.

## 2. Требования

| Параметр | Требование |
|---|---|
| Touch target | Минимум 44×44px, для основных действий («Принять», «Готово») — высота ≥ 56px, во всю ширину карточки |
| Скролл | Только вертикальный, никогда горизонтальный на планшетных экранах (768–1023px) |
| Контраст | Крупный, разборчивый текст статусов и параметров товара — не полагаться только на цвет (добавлять иконку/текст, см. подход к бейджам единиц измерения в `docs/TZ.md`) |
| Без вложенных меню | Ключевые действия сотрудника — прямые кнопки на карточке, не спрятаны в `⋯` меню (тот `RowActions`/`⋯`, что сейчас есть для менеджера — остаётся для менеджерских действий, не для «Принять»/«Готово») |
| Один экран = одно действие | На экране очереди — не более одного основного CTA на карточку |

## 3. Ключевые экраны (детали — в [02-production.md](./02-production.md))

- Очередь «Новые» → кнопка «Принять заказ».
- «В работе у меня» → кнопка «Готово».
- Обе кнопки без диалогов подтверждения (действие обратимо менеджером).

## 4. Что НЕ трогаем

Существующий десктопный интерфейс менеджера (`OrdersTable` со `StatusDropdown`, доска/список, фильтры) остаётся как есть — он уже хорошо проработан (портал для дропдаунов, доска по статусам, адаптивные карточки на мобильном). Новые экраны для сотрудников — это **дополнительный** режим отображения `/orders` для роли `employee`, не переделка существующего.

## 5. Проверка перед сдачей

Каждый экран для сотрудника тестировать вручную на реальном или эмулированном планшетном разрешении (768–1024px, touch-эмуляция в DevTools) — команда `/run`, если нужно поднять и открыть приложение локально.
